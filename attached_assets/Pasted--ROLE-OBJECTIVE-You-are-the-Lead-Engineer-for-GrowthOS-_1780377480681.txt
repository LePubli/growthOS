Your mission is to implement **Plugin 2: Meeting Intelligence**.

This plugin allows users to upload meeting recordings, generates transcripts (mocked), extracts key insights, and AUTOMATICALLY indexes the transcript into Growth Memory.

# ARCHITECTURE CONSTRAINTS
- **Backend**: `artifacts/api-server/src/...`
- **Frontend**: `artifacts/growthos/src/...`
- **Database**: PostgreSQL (use existing connection).
- **Storage**: For now, use local disk storage or simple DB text storage for "files" (avoid complex S3 setup for now).
- **AI Mock**: Simulate the transcription process (return structured JSON: summary, action items, objections) after a short delay.

# PHASE 1: DATABASE (PostgreSQL)
1. Create migration: `artifacts/api-server/db/migrations/003_meeting_intelligence.sql`.
2. Create table `meetings`:
   - `id` (uuid), `title` (text), `status` (enum: 'pending', 'processing', 'completed', 'error'),
   - `transcript` (text), `summary` (text), `action_items` (jsonb),
   - `created_at`, `updated_at`.

# PHASE 2: BACKEND SERVICE & API
1. Create service: `artifacts/api-server/src/lib/plugin-meeting-intelligence/MeetingService.ts`.
   - `createMeeting(data)`: Creates entry with status 'pending'.
   - `processMeeting(id)`: Mocks the AI pipeline. Updates status to 'completed' and generates mock text/JSON.
   - **CRITICAL**: Upon completion, call the `MemoryService.indexDocument()` from Plugin 1 to index the transcript. (Import MemoryService carefully).
2. Create routes: `artifacts/api-server/src/routes/v1/plugins/meetings.ts`.
   - `POST /`: Upload/Create meeting.
   - `GET /`: List meetings.
   - `GET /:id`: Get meeting details.
   - `POST /:id/process`: Trigger processing (for manual trigger, or auto-trigger on creation).
3. **Register Routes**: Mount in `artifacts/api-server/src/routes/v1/index.ts`.
