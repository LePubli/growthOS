# OBJECTIF : PLUGIN E-RÉPUTATION (PHASE 2 - FRONTEND UI & INTÉGRATION GROWTHOS)

Le backend et la DB sont en place. Tu vas maintenant construire l'interface utilisateur (Frontend) et connecter ce plugin au reste de l'écosystème GrowthOS.

# CONTEXTE TECHNIQUE FRONTEND
- Stack : React 18, Vite, TypeScript, Tailwind CSS, Radix UI, Recharts (pour les graphiques).
- State Management : TanStack Query (React Query).
- Routing : Wouter.
- Design : Utilise les composants UI existants dans `artifacts/growthos/src/components/ui/` (Card, Button, Input, Badge, etc.) pour garder la cohérence visuelle.

# PHASE 2.4 : INTÉGRATION CRUCIALE AVEC GROWTHOS (LE "CÂBLAGE")
C'est la partie la plus importante. Le plugin ne doit pas être isolé.

1. **Interconnexion avec Signal Intelligence (Plugin 8)** :
   - Dans le backend, quand `SentimentAnalyzer` détecte une mention très négative (score < 30), il doit émettre un événement via l'EventBus :
     `pluginEventBus.emit('signal.received', { type: 'reputation_crisis', accountId: campaign.targetId, title: 'Crise réputationnelle détectée', impactScore: 90 })`.
   - Cela fera apparaître l'alerte directement dans le radar commercial de GrowthOS.

2. **Interconnexion avec Growth Memory (Plugin 1)** :
   - Quand un audit SEO/GEO est terminé, le backend doit indexer un résumé dans la Memory :
     `memoryService.indexDocument({ sourceType: 'ereputation_audit', content: `Audit SEO pour ${target}: Score ${score}. Points forts: ${strengths}. Points faibles: ${weaknesses}.`, metadata: { targetId, score } })`.

3. **Interconnexion avec AI SDR (Plugin 4)** :
   - Si un compte a un score de réputation > 85, l'AI SDR doit pouvoir utiliser cette info pour personnaliser ses emails (ex: "Félicitations pour votre excellente image de marque..."). Assure-toi que le champ `reputation_score` est accessible dans le contexte de l'Account.
