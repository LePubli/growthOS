# OBJECTIF : CRÉER UNE SUITE DE TESTS E2E COMPLÈTE POUR GROWTHOS

GrowthOS a beaucoup de fonctionnalités implémentées mais peu de tests automatisés. Il faut créer une suite de tests E2E robuste qui valide le bon fonctionnement de toutes les fonctionnalités critiques, de bout en bout.

# PHASE 1 : INFRASTRUCTURE DE TEST

## 1.1 Configuration
Crée `artifacts/api-server/src/tests/setup.ts` :
- Configuration de la base de données de test (schema séparé ou rollback après chaque test)
- Génération de JWT tokens de test (admin, commercial, client)
- Helpers pour créer des entités de test (prospect, account, deal, etc.)
- Cleanup automatique après chaque test suite

## 1.2 Client HTTP de test
Crée `artifacts/api-server/src/tests/test-client.ts` :
- Wrapper autour de axios/supertest
- Injection automatique du token JWT
- Gestion des erreurs et assertions
- Logs détaillés des requêtes/réponses

# PHASE 5 : RAPPORT ET COUVERTURE

Crée un script `artifacts/api-server/src/scripts/test-report.ts` qui :
1. Exécute tous les tests
2. Génère un rapport HTML avec :
   - Nombre de tests passés/échoués
   - Couverture par module (prospects, deals, signals, etc.)
   - Temps d'exécution total
   - Graphiques de couverture
3. Identifie les routes API non testées
4. Recommande les tests prioritaires à ajouter

# RÈGLES STRICTES
1. Chaque test doit être indépendant (pas de dépendance entre tests)
2. Cleanup automatique après chaque test (rollback DB ou suppression entités)
3. Les tests ne doivent PAS modifier les données de production
4. Utilise des données de test réalistes (noms français, emails valides, etc.)
5. Logs détaillés pour chaque assertion échouée
6. Timeout de 10 secondes par test maximum
7. Les tests doivent pouvoir tourner en parallèle (isolation complète)

# COMMANDE D'EXÉCUTION
Ajoute dans `package.json` :
```json
"test:e2e": "tsx src/tests/run-all-tests.ts",
"test:e2e:report": "tsx src/scripts/test-report.ts",
"test:e2e:coverage": "tsx src/tests/run-all-tests.ts --coverage"
