# OBJECTIF : TRANSFORMER GROWTHOS EN SAAS ENTERPRISE COMPLET

Tu es un Lead Fullstack Engineer expert en architectures SaaS multi-tenant. Tu vas implémenter les 13 fonctionnalités manquantes identifiées dans l'audit de GrowthOS, organisées en 4 niveaux de priorité.

# ⚠️ CONTRAINTES ARCHITECTURALES CRITIQUES

1. **Architecture Plugins Existante** : GrowthOS utilise un système de plugins modulaire. Chaque nouvelle fonctionnalité DOIT être un plugin indépendant avec son propre manifest.
2. **Stack Technique** :
   - Backend : Express + TypeScript + Drizzle ORM + PostgreSQL
   - Frontend : React 18 + Vite + TypeScript + Tailwind CSS + Radix UI + Recharts
   - Auth : JWT avec refresh tokens
   - Real-time : SocketIO (déjà partiellement implémenté)
3. **Multi-Tenancy** : Toutes les nouvelles tables DOIVENT avoir un `tenant_id` avec Row-Level Security PostgreSQL
4. **Ne casse AUCUNE fonctionnalité existante** : Les 35 fonctionnalités actuelles doivent continuer à fonctionner
5. **Interconnexion** : Chaque nouveau plugin doit s'intégrer avec Growth Memory, Signal Intelligence, et le EventBus

# 🎯 PHASE 1 : NIVEAU 1 - CRITIQUE (Bloque la vente) - 4 semaines

## 1.1 Multi-Tenancy Réel (P0 - 2 semaines)

### Architecture
- Ajouter `tenant_id UUID` sur TOUTES les tables existantes (prospects, accounts, deals, signals, meetings, sequences, etc.)
- Créer la table `tenants` avec : id, name, domain, plan (starter/pro/enterprise), is_active, created_at
- Implémenter Row-Level Security (RLS) PostgreSQL sur toutes les tables
- Créer un middleware `requireTenant` qui extrait le tenant_id du JWT et le passe à toutes les requêtes

### Fichiers à créer/modifier
1. `artifacts/api-server/db/migrations/030_multi_tenant.sql` :
   - ALTER TABLE sur toutes les tables pour ajouter tenant_id
   - CREATE TABLE tenants
   - ENABLE ROW LEVEL SECURITY sur toutes les tables
   - CREATE POLICY tenant_isolation USING (tenant_id = current_setting('app.current_tenant')::uuid)

2. `artifacts/api-server/src/middlewares/tenantIsolation.ts` :
   - Middleware Express qui extrait tenant_id du JWT
   - Set `app.current_tenant` pour RLS PostgreSQL
   - Injection de tenant_id dans req.tenantId

3. Modifier `artifacts/api-server/src/routes/v1/*.ts` (toutes les routes) :
   - Ajouter `requireTenant` après `requireAuth`
   - Toutes les queries doivent filtrer par tenant_id

4. `artifacts/api-server/src/lib/tenant/TenantService.ts` :
   - CRUD complet des tenants
   - Gestion des plans et quotas
   - Activation/désactivation de tenants

### Migration des données existantes
- Script de migration qui assigne toutes les données existantes au tenant "default"
- Création automatique du tenant par défaut au premier démarrage
