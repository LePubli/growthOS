# OBJECTIF : FINALISATION COMPLÈTE DE GROWTHOS - DÉ-MOCKAGE SYSTÉMATIQUE & INTERCONNEXION TOTALE

GrowthOS a une architecture solide avec 35+ modules, mais la majorité des pages sont des coquilles vides : données mockées, boutons non fonctionnels, routes API 404, pas de vraies relations entre les entités. Tu dois transformer chaque page en fonctionnalité 100% opérationnelle connectée à de vraies données PostgreSQL.

# ⚠️ RÈGLES CRITIQUES NON NÉGOCIABLES
1. Ne casse AUCUNE fonctionnalité existante qui fonctionne
2. Toutes les données doivent venir de PostgreSQL (zéro mock en UI)
3. Multi-tenancy : toutes les tables doivent avoir tenant_id
4. Interconnexion : chaque plugin doit communiquer avec les autres via EventBus
5. Tests E2E obligatoires après chaque phase
6. Boutons = actions réelles (pas de "coming soon")

# PHASE 4 : INTERCONNEXION TOTALE DES PLUGINS

## 4.1 EventBus - Événements Cross-Plugins
Crée `artifacts/api-server/src/lib/integrations/cross-plugin-events.ts` qui enregistre les listeners :

**Prospect créé** → 
- Indexe dans Growth Memory
- Déclenche workflows matching
- Envoie webhook sortant si configuré

**Deal stage changé** →
- Met à jour Revenue Intelligence forecast
- Déclenche workflows matching
- Notifie commercial assigné
- Envoie webhook sortant

**Signal détecté** →
- Crée notification temps réel
- Déclenche workflows matching
- Met à jour Account Health Score si lié à un compte

**Audit E-Réputation terminé** →
- Émet `erep.score.updated` → met à jour accounts.reputation_health_score
- Émet `erep.alert` si score < 40 → crée signal dans Signal Intelligence
- Indexe résumé dans Growth Memory
- Notifie via SocketIO

**Séquence email envoyée** →
- Track ouverture/clic → crée activité CRM
- Met à jour statistiques séquence
- Déclenche étape suivante si configurée

## 4.2 Account Intelligence - Health Score Unifié

- Activité récente (40%)

## 4.3 Executive Command Center - Vue Consolidée
