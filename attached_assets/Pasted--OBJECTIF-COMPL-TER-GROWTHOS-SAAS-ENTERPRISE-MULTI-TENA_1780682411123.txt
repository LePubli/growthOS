# OBJECTIF : COMPLÉTER GROWTHOS - SAAS ENTERPRISE (MULTI-TENANCY, BILLING, COLLABORATION, RGPD)

Contexte : GrowthOS est opérationnel avec ses 35 modules core. Certaines features UI ont été ajoutées récemment (Tâches, Onboarding, Referral, Help Center, Export CSV). 
Cependant, les fondations critiques pour vendre en SaaS (Multi-Tenancy, Facturation Stripe, Sécurité avancée, Collaboration temps réel) ne sont pas encore implémentées ou sont à l'état de "stub".

Tu es un Lead Fullstack Engineer. Ta mission est d'implémenter les briques manquantes critiques listées ci-dessous.

# ⚠️ RÈGLES D'OR
1. **Multi-Tenancy OBLIGATOIRE** : Toutes les nouvelles tables DOIVENT avoir `tenant_id`. 
2. **Sécurité** : Middleware `requireTenant` sur toutes les nouvelles routes.
3. **Ne casse rien** : L'existant (Prospects, Deals, Signals, Tâches, Onboarding, etc.) doit continuer à fonctionner.
4. **Interconnexion** : Utilise les services existants (`EventBus`, `NotificationService`, `AuditService`) quand c'est pertinent.

# 🚀 PHASE 1 : MULTI-TENANCY & FACTURATION (CRITIQUE P0)

## 1.1 Multi-Tenancy Réel (Le Socle)
Actuellement, les données ne sont pas isolées par client. Il faut créer l'architecture Multi-Tenant.

### Backend
1. **Migration DB** : `artifacts/api-server/db/migrations/040_tenants.sql`
   - Créer table `tenants` (id, name, domain, plan, status, created_at).
   - Ajouter colonne `tenant_id` (UUID, FK) sur TOUTES les tables critiques existantes : `prospects`, `accounts`, `deals`, `signals`, `tasks`, `users`, `activities`.
   - Créer index sur `tenant_id` pour chaque table.
   - *Note : Pour l'instant, on ne fait pas de RLS PostgreSQL complexe, on gère l'isolation via le middleware applicatif.*

2. **Middleware** : `artifacts/api-server/src/middlewares/tenantIsolation.ts`
   - Extraire `tenantId` du JWT de l'utilisateur connecté.
   - Injecter `req.tenantId` dans la requête.
   - Créer une fonction utilitaire `getTenantScope(req)` qui retourne `{ tenant_id: req.tenantId }` à utiliser dans les clauses `WHERE` des requêtes Drizzle.

3. **Service** : `artifacts/api-server/src/lib/tenant/TenantService.ts`
   - `createTenant(data)` : Crée un nouveau tenant.
   - `getTenant(tenantId)` : Récupère les infos du tenant.

4. **Mise à jour des Routes** :
   - Modifier `artifacts/api-server/src/routes/v1/*.ts` (prospects, deals, signals, tasks, etc.) pour utiliser le middleware `requireTenant` et filtrer les résultats par `tenant_id`.
   - *Exemple : `select().from(tasks).where(eq(tasks.tenant_id, req.tenantId))`.*

## 1.2 Facturation Stripe & Quotas (P0)
Implémenter le vrai système de facturation et de limites d'usage.

### Backend
1. **Migration DB** : `artifacts/api-server/db/migrations/041_billing.sql`
   - Table `subscriptions` (tenant_id, stripe_customer_id, stripe_subscription_id, plan, status, current_period_end).
   - Table `invoices` (tenant_id, stripe_invoice_id, amount, status, url).
   - Table `usage_limits` (tenant_id, resource, limit_value, current_usage, period_start).
   - Table `api_keys` (tenant_id, key_hash, permissions, expires_at).

2. **Service** : `artifacts/api-server/src/lib/billing/StripeService.ts`
   - `createSubscription(tenantId, priceId)` : Crée l'abonnement Stripe.
   - `handleWebhook(event)` : Gère `invoice.paid`, `customer.subscription.deleted`.
   - `checkUsage(tenantId, resource)` : Vérifie si le quota est dépassé (ex: 1000 prospects/mois).
   - `incrementUsage(tenantId, resource)` : Incrémente le compteur.

3. **Middleware** : `artifacts/api-server/src/middlewares/usageLimit.ts`
   - À placer après `requireTenant`.
   - Vérifie `checkUsage` avant les actions coûteuses (création prospect, envoi email, enrichissement).
   - Retourne `402 Payment Required` si quota dépassé.

4. **Routes** : `artifacts/api-server/src/routes/v1/billing.ts`
   - `GET /billing/subscription` : Statut actuel.
   - `POST /billing/checkout` : Crée session Stripe.
   - `POST /billing/webhook` : Endpoint public pour Stripe.
   - `GET /billing/usage` : Consommation actuelle.

### Frontend
1. **Page** : `artifacts/growthos/src/pages/BillingPage.tsx`
   - Affiche le plan actuel, la date de fin de période.
   - Graphique d'utilisation (Prospects utilisés / Limite).
   - Bouton "Mettre à jour" ou "Annuler" (via lien Stripe Customer Portal).

### Frontend

## 3.2 API Publique & Rate Limiting
Permettre l'accès programmatique sécurisé.

### Backend
1. **Service** : `artifacts/api-server/src/lib/api/ApiKeyService.ts`
   - `generateApiKey(tenantId, permissions)` : Crée une clé API.
   - `validateApiKey(key)` : Vérifie la clé et retourne le tenant associé.
   - `checkRateLimit(apiKeyId)` : Vérifie le nombre de requêtes/minute.

2. **Middleware** : `artifacts/api-server/src/middlewares/apiKeyAuth.ts`

   - Applique le rate limiting.

3. **Routes** : `artifacts/api-server/src/routes/v1/public-api.ts`

### Frontend
